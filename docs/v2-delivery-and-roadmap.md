# V2 交付与后续路线

## 1. 版本目标

V2 将 Control Your Skills 从“导入和复制工具”升级为本地 Skill 控制中心。系统现在围绕一个中心仓库管理主版本，并在所有破坏性写入前提供差异、确认、快照和回滚。

旧版设计文档 `skill-sync-center-design.md` 与 `skill-sync-center-implementation-plan.md` 定义了中心仓库、分类和同步 MVP。V2 保留这条主线，并补齐版本生命周期、批量治理和可信 GitHub 更新。

## 2. 已交付范围

| 阶段 | 交付能力 | 验收结果 |
| --- | --- | --- |
| V2.1 | 目录级差异、同步确认、执行前哈希校验、目标快照、操作审计 | 覆盖和采纳都必须经过预览；目标变化后旧预览失效 |
| V2.2 | `SKILL.md` 编辑/预览、版本历史、置顶、回滚、快照保留策略 | 保存和回滚前自动快照；损坏快照无法恢复 |
| V2.3 | 标签、扩展搜索、分类/标签筛选、批量分类和标签操作 | 标签持久化；筛选结果可多选并批量更新 |
| V2.4 | 公开 GitHub 仓库安装和更新审查 | 只复制文件；更新前展示差异并创建可回滚快照 |
| V2.4.1 | 客户端软件更新 | 正式版自动或手动检查；在客户端内下载并重启安装 |

## 3. 关键工作流

### 3.1 安全同步

1. 用户选择“覆盖目标”或“采纳目标”。
2. 系统计算中心仓库与目标目录的哈希和逐文件差异。
3. 用户检查新增、修改、删除和文本补丁。
4. 系统在执行前重新计算哈希。任一侧变化都会使预览失效。
5. 系统保存被覆盖目录的快照，再进行原子目录替换。
6. 系统记录方向、决策、前置哈希、快照和结果。

### 3.2 内容编辑与回滚

1. 用户在中心仓库打开“内容与版本”。
2. 用户编辑或预览 `SKILL.md`。
3. 保存时，系统校验打开页面时的目录哈希。
4. 系统保存编辑前版本，原子替换目录并重新解析名称、slug 和描述。
5. 用户可置顶重要版本，或恢复任一中心仓库快照。

### 3.3 可信 GitHub 安装和更新

1. 用户把公开 GitHub 仓库加入暂存区并完成解析。
2. 系统下载未经认证的 `HEAD.zip`，限制为 100 MB。
3. 系统拒绝 HTTP、凭据 URL、本机地址和私有网络目标。
4. 系统识别包含 `SKILL.md` 的目录，展示仓库版本与目标目录的差异。
5. 用户确认后，系统重新下载并校验远端、本地哈希和目标路径。
6. 更新已有 Skill 时，系统先创建 `before-remote-update` 快照。

可信安装不会运行 `npm install`、Shell 脚本或仓库提供的其他命令。

### 3.4 客户端软件更新

1. Windows 或已签名的 macOS 正式版启动 10 秒后检查 GitHub Releases。
2. 用户也可从顶栏手动检查，并查看当前版本和检查结果。
3. 发现新版本后，用户确认下载；客户端展示下载进度。
4. 下载完成后，用户选择重启并安装。关闭客户端也会安装已下载的更新。

Windows 发布 NSIS 安装包和 `latest.yml`。macOS 发布 DMG、ZIP 和 `latest-mac.yml`；自动更新要求 Developer ID 签名。未签名的 macOS 构建会停用更新入口。

## 4. 数据与兼容性

V2 对现有 SQLite 数据库采用增量迁移：

- `installed_skills.tags` 保存规范化标签。
- `skill_snapshots` 保存中心仓库或目标目录的版本快照。
- `sync_operations` 保存安全同步审计记录。
- `settings` 增加快照数量和容量限制。

旧数据库首次启动时自动补充字段和默认值。默认每个 Skill 保留 20 个普通快照，全部快照容量上限为 1024 MB。用户可在设置页调整为 5–100 个和 256–10240 MB。

## 5. 验证基线

每个功能提交前执行以下检查：

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

V2.4.1 完成时的自动化基线为 15 个测试文件、53 项测试。生产构建同时验证 Next.js 静态页面、Electron 主进程/预加载脚本和发布目录准备流程。

## 6. V3 计划

### V3.0：发现与质量

- 使用自然语言检索本地和可信来源 Skill。
- 增加来源信誉、许可证、更新时间和兼容性信息。
- 在安装前检查危险命令、超大文件和异常目录结构。
- 建立可解释的质量评分，不自动阻止用户选择。

### V3.1：更新自动化

- 为 GitHub 来源配置手动、定时或启动时检查。
- 将可用更新汇总为审查队列。
- 支持批量预览，但每次写入继续经过确认、哈希校验和快照。
- 增加维护窗口和通知，不默认静默更新。

### V3.2：可观测性

- 展示同步、编辑、回滚和远端更新的统一时间线。
- 展示快照容量、增长趋势和清理结果。
- 导出脱敏诊断包，缩短失败排查时间。
- 增加中心仓库和各同步目标的健康度摘要。

## 7. V4 方向

V4 再评估团队 Registry、审批、角色权限和跨设备同步。团队能力必须复用 V2 的审查、快照、审计和回滚语义，并为远端身份、签名和供应链验证补充独立安全设计。
